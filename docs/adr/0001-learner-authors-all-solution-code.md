# The Learner authors Solution code; assistance is an opt-in, bounded exception

The agent writes the Harness (specs, Test suites, starter repo); by default (Solo) every line of Solution code is written by the Learner. Claude Code's Learning output style lets the agent write most of the code and leaves trivial TODOs, which trains nothing; the skill we want to rebuild is Unassisted authorship.

The Learner may opt into an Assistance mode per Project or per Stage: Pair (the agent writes boilerplate around the Stage's concept, which the Learner then walks through) or Lead (the agent implements the Learner's written Approach, and the Learner answers questions on the result). Directing AI is a skill worth practising, and the evidence says AI use preserves learning when the human generates first and comprehends after, and destroys it when they delegate. So in every mode debugging, Drills, Concept checks and Design reviews stay the Learner's, and every agent edit to Solution code is logged so reviews, Dials and the Retrospective can tell whose code is whose.

The rule is carried by the Project repo's `AGENTS.md` (portable across agent harnesses). Mechanical enforcement (a Claude Code hook that reads the current mode) is an optional per-harness adapter: the main threat is the agent's default of fixing code when asked about it, which instructions address; a Learner who chooses to bypass the rule is outside what a practice tool should police. Boilerplate not worth learning ships in the starter repo before Stage 1.
